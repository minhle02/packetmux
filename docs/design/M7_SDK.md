# M7 — Async SDK (Python and TypeScript): design

Status: approved, not implemented.
Requirements: `docs/requirements/INTENT.md` (§5.12 to §5.16, NFR-SDK, D13 to D23).
Depends on M6: `HELLO.resuming`, `Reason.SESSION_NOT_FOUND`, and the conformance runners.

The SDK is the async layer over the sync binding (M4). A consumer implements a `Transport` and calls
`connect` or `Server.serve`. Everything else in the host loop moves in here. There is no protocol
logic in the SDK: frames, stream states, scheduling and keepalive stay in the core.

Python and TypeScript have the same classes and the same control flow. §5 onwards is written once, in
Python-like pseudocode. Naming follows each language, and durations follow the existing bindings:
seconds in Python, milliseconds in TypeScript.

## 1. What a consumer writes

```python
from packetmux import connect

async def dial(session_id: str) -> Transport:
    return await MyWebSocketTransport.open(f"wss://host/mux?session={session_id}")

async with await connect(dial) as client:
    stream = await client.open_stream("echo")
    await stream.write(b"hello")
    await stream.send_eof()
    async for chunk in stream:
        print(chunk)
```

```ts
import { connect } from 'packetmux'

const dial = (sessionId: string) => MyWebSocketTransport.open(`wss://host/mux?session=${sessionId}`)

const client = await connect(dial)
const stream = await client.openStream('echo')
await stream.write(new TextEncoder().encode('hello'))
await stream.sendEof()
for await (const chunk of stream) console.log(chunk)
await client.close()
```

```python
from packetmux import Server

async def echo(request: IncomingStream) -> None:
    stream = request.accept()
    async for chunk in stream:
        await stream.write(chunk)

server = Server(handlers=[("echo", echo)])

async def on_websocket(socket) -> None:           # however the web framework calls you
    await server.serve(MyWebSocketTransport(socket))
```

`open_stream` waits for a connection, for at most `connect_timeout`, and does **not** wait for
`OPEN_OK`, so a caller can write at once (FR-AST-1).

### 2.4 Inbound streams

Either role can receive streams (FR-STR-3). A handler is registered by kind, or by a stream type
(§2.5), and is given a request, which it accepts or rejects:

```python
Handler = Callable[[IncomingStream], Awaitable[None]]
Handlers = Iterable[tuple[str | type, Handler]]    # TS: Array<[string | StreamTypeFactory, Handler]>

class IncomingStream:
    kind: str
    params: bytes | T                              # T when registered by stream type
    session: Client | ServerSession

    def accept(self) -> Stream: ...
    def reject(self, code: Reason, message: bytes = b"") -> None: ...
```

Accepting is explicit so that a handler can do async work first, such as dialing a TCP target, and
reject with `CONNECT_FAILED` if that fails. Data that arrives meanwhile waits in the stream's buffer
(FR-STR-7). Accepting on the first write would deadlock a handler that reads first against a peer
that calls `wait_accepted`.

| The handler | The SDK then |
|---|---|
| Raises `Reject(code, message)`, or raises anything else, before accepting | Rejects: with that code, or with `CONNECT_FAILED` |
| Returns without accepting | Rejects with `POLICY_DENIED` |
| Raises after accepting | Logs it and resets the stream with `KILLED` |
| Returns after accepting | Sends `EOF` if the handler did not. The stream stays until the peer's `EOF`, so a late reply can still be read |

### 2.5 Typed params

A stream type is a kind plus its params fields, declared once per language (FR-AST-8). On the wire,
params are still opaque bytes. The SDK turns them into JSON and back, and the core never looks inside.

```python
from packetmux import stream_type

@stream_type("tcp-forward")
@dataclass
class TcpForward:
    host: str
    port: int
    timeout: float | None = None                   # nullable, with a default

stream = await client.open_stream(TcpForward(host="127.0.0.1", port=5037))

async def forward(request: IncomingStream[TcpForward]) -> None:
    target = request.params                        # already decoded and checked
    ...

server = Server(handlers=[(TcpForward, forward)])
```

```ts
import { defineStream } from 'packetmux'

const TcpForward = defineStream('tcp-forward', {
  host: 'string',
  port: 'int',
  timeout: { type: 'float?', default: null }       // nullable, with a default
})

const stream = await client.openStream(TcpForward({ host: '127.0.0.1', port: 5037 }))

const forward = async (request: IncomingStream<typeof TcpForward>): Promise<void> => {
  const target = request.params                    // typed, decoded and checked
}

const server = new Server({ handlers: [[TcpForward, forward]] })
```

TypeScript types do not exist at runtime, so `defineStream` takes the fields as values, and infers
the static type from them. Python reads the same information from the class annotations. Neither
gives validation for free, so each SDK has its own validator of about 30 lines, with no schema
library (NFR-SDK-2). A consumer only declares the type.

Raw bytes stay available for binary params or a consumer's own format:
`open_stream("kind", b"...")`, with the handler registered by its string kind.

Field names go on the wire exactly as declared, with no camelCase conversion, so a Python `max_size`
needs a TypeScript `max_size`. `bytes` fields are not supported, because JSON has no binary type.

### 2.6 Server

```python
class Server:
    def __init__(
        self,
        handlers: Handlers | None = None,
        authorize: Authorize | None = None,
        capabilities: bytes = b"",
        options: ServerOptions | None = None,
    ) -> None: ...

    async def serve(self, transport: Transport, context: Any = None) -> None: ...
    def sessions(self) -> list[ServerSession]: ...
    async def close(self, code: Reason = Reason.OK) -> None: ...

class ServerSession:
    session_id: str
    connected: bool
    data: Any                                      # what authorize returned
    rtt_ms: int | None

    async def open_stream(self, target: str | StreamType, params: bytes = b"") -> Stream: ...  # fails if disconnected
    def streams(self) -> list[StreamInfo]: ...
    async def close(self, code: Reason = Reason.OK) -> None: ...

@dataclass
class ConnectRequest:
    session_id: str
    capabilities: bytes
    resuming: bool
    context: Any                                   # what the consumer passed to serve()
    session: ServerSession | None                  # the existing one, or None

Authorize = Callable[[ConnectRequest], Awaitable[Any]]  # returns data, or raises Refuse(code)
```

`serve` returns when that connection ends. The TypeScript `Server` has the same members and is meant
for Node (FR-SRV-8).

`authorize` is how a consumer stops a stranger taking over a session (FR-SRV-3): it returns who the
peer is, the SDK stores that as `session.data`, and on a re-dial the hook compares it with
`request.session.data`.

### 2.7 Errors

The same names in both languages (FR-SDK-6). All extend `PacketMuxError`.

| Error | Raised when |
|---|---|
| `TransportClosed` | By a Transport, once it has closed (FR-TP-3). Only a consumer's Transport code sees it |
| `StreamReset(code)` | Reading, writing or waiting on a reset stream |
| `StreamClosed` | Writing after `send_eof`, or after a clean close |
| `NoConnection` | No connection within `connect_timeout`, or `ServerSession` is disconnected |
| `SessionClosed(code)` | The session has ended. Also the value of `close_error` |
| `SessionNotFound` | Extends `SessionClosed`. The server no longer has the session (FR-CLI-4a) |
| `LimitExceeded` | `max_streams` reached, or stream IDs exhausted |
| `InvalidParams` | Outgoing typed params do not match their type. Nothing is sent |

Raised by consumer code, for the SDK:

| Error | Meaning |
|---|---|
| `GiveUp(reason)` | From a dial function: stop reconnecting. The client closes with this error (FR-CLI-3) |
| `Reject(code, message)` | From a handler: reject the stream |
| `Refuse(code)` | From `authorize`: refuse the connection |

## 3. Transport

```python
class Transport(ABC):
    max_message_size: int = 1 << 20

    @abstractmethod
    async def send(self, message: bytes) -> None: ...    # may wait; accepted is not delivered
    @abstractmethod
    async def recv(self) -> bytes: ...                   # the next whole message
    @property
    @abstractmethod
    def buffered_amount(self) -> int: ...                # accepted by send, not yet on the wire
    @abstractmethod
    async def close(self) -> None: ...                   # idempotent

    async def wait_buffer_below(self, limit: int) -> None:
        """Override with an event-based version where possible. This fallback polls."""
```

```ts
interface Transport {
  readonly maxMessageSize: number
  readonly bufferedAmount: number
  send(message: Uint8Array): Promise<void>
  recv(): Promise<Uint8Array>
  waitBufferBelow(limit: number): Promise<void>
  close(): Promise<void>
}

/** For sources that push: WebSocket, data channel (FR-TP-6). */
abstract class PushTransport implements Transport {
  protected abstract sendMessage(message: Uint8Array): void | Promise<void>
  protected abstract closeSource(): void
  abstract readonly bufferedAmount: number

  protected handleMessage(message: Uint8Array): void    // queues it for recv, or wakes recv
  protected handleClose(error?: Error): void            // fails recv, send and waiters
  protected handleBufferLow(): void                     // wakes waitBufferBelow
}
```

Both languages pull with `recv`, unlike RemoteDevice's TS contract, which pushes through `onMessage`.
That gives both one reader loop, and one conformance layer. `PushTransport` carries the queue, so
FR-TP-2 holds without the consumer writing it: messages wait in the queue from the moment the source
opens.

The memory transport in `packetmux.testing` adds the controls that FR-TP-5 needs:

```python
a, b = memory_transport_pair()
a.stall()              # wait_buffer_below stops returning: the send loop parks, as on a full link
a.release()
await a.break_connection()
```

## 4. Layers

```
Consumer
   │  Client / Server / ServerSession     lifecycle, reconnect, grace, session registry
   │  Stream / IncomingStream             read buffer, write loop, handlers
   ▼
SessionHost                               one per session: owns the core, drains events, one timer
   │  Connection                          one per Transport: reader and sender loops
   ▼                     ▼
core.Session (sync)    Transport
```

`Client` and `ServerSession` are thin. All host rules (FR-SDK-4) sit in `SessionHost`, `Connection`
and `Stream`, so both roles share them.

## 5. SessionHost and Connection

Every core call goes through `_call`, so no path can skip the drain.

```python
class SessionHost:
    def __init__(self, core, handlers, options, on_connected, on_lost, on_closed): ...
    # core, connection, streams: dict[int, Stream], replacing = False

    def _call(self, fn, *args):
        result = fn(*args)
        self._after_call()
        return result

    def _after_call(self):
        while (event := self.core.poll_event()) is not None:
            self._on_event(event)                # synchronous: it only buffers and wakes
        if self.core_ended:                      # WASM memory is not collected
            self._release_core()
            return
        self._arm_timer()                        # one timer; re-armed only for an earlier deadline
        if self.connection is not None:
            self.connection.wake()

    def attach(self, transport, first_message=None) -> Connection:
        if self.connection is not None:          # the client re-dialed before the old one died
            self.replacing = True
            self._call(self.core.on_connection_lost)
            self.replacing = False
        self.core.attach_connection(now_ms())
        connection = Connection(self, transport)
        self.connection = connection
        if first_message is not None:            # a server has already read the HELLO
            self.core.on_message(first_message, now_ms())
        connection.start()
        self._after_call()
        return connection

    def feed(self, connection, message):
        if connection is self.connection:        # a replaced connection may report late
            self._call(self.core.on_message, message, now_ms())

    def transport_lost(self, connection):
        if connection is self.connection:
            self._call(self.core.on_connection_lost)

    def poll_transmit(self):
        return self._call(self.core.poll_transmit)

    def _on_event(self, event):
        match event.type:
            case DATA:            streams[id].on_data(event.data)
            case EOF:             streams[id].on_eof()
            case WRITABLE:        streams[id].on_writable()
            case STREAM_ACCEPTED: streams[id].on_accepted()
            case STREAM_CLOSED:   streams.pop(id).on_closed(event.code)
            case STREAM_OPENED:   self._on_stream_opened(event)
            case CONNECTED:       self.on_connected(event)
            case DISCONNECTED:
                connection, self.connection = self.connection, None
                connection.finish()
                self.on_lost(event, replaced=self.replacing)
            case SESSION_CLOSED:
                connection, self.connection = self.connection, None
                if connection: connection.finish()
                cancel_handler_tasks()
                self.core_ended = True
                self.on_closed(event)

    def _on_stream_opened(self, event):
        entry = self.handlers.get(event.kind)    # (handler, stream type or None)
        if entry is None:
            self.core.reject_stream(event.stream_id, UNSUPPORTED_KIND)  # drained by this same loop
            return
        handler, stream_type = entry
        params = event.params
        if stream_type is not None:
            try:
                params = decode_params(stream_type, event.params)        # §6.4
            except InvalidParams as e:
                self.core.reject_stream(event.stream_id, PROTOCOL_ERROR, str(e).encode())
                return
        stream = Stream(self, event.stream_id, event.kind)
        self.streams[event.stream_id] = stream
        spawn_handler(handler, IncomingStream(stream, event.kind, params))       # §6.3
```

```python
class Connection:
    def __init__(self, host, transport): ...
    # finished = False, work = Event()

    def start(self):
        self.reader_task = spawn(self._reader())
        self.sender_task = spawn(self._sender())

    def wake(self):
        self.work.set()

    def finish(self):
        """The session is done with this connection. GOAWAY may still be in the sender's hands."""
        if self.finished:
            return
        self.finished = True
        self.work.set()
        spawn(self._shutdown())

    async def _reader(self):
        try:
            while not self.finished:
                self.host.feed(self, await self.transport.recv())
        except TransportClosed:
            self.host.transport_lost(self)

    async def _sender(self):
        try:
            while not self.finished:
                await self.transport.wait_buffer_below(self.inflight_limit)
                if self.finished:                # replaced while waiting: what is queued now
                    break                        # belongs to the new connection
                message = self.host.poll_transmit()
                if message is None:
                    if not self.finished:
                        self.work.clear()
                        await self.work.wait()
                    continue
                await self.transport.send(message)   # a GOAWAY just taken still goes out
        except TransportClosed:
            self.host.transport_lost(self)

    async def _shutdown(self):
        await wait_for_at_most(self.sender_task, drain_timeout)
        await wait_for_at_most(self.transport.wait_buffer_below(1), drain_timeout)
        cancel(self.sender_task, self.reader_task)
        await self.transport.close()
        self.closed.set()
```

A loop that fails with anything other than `TransportClosed` logs it and reports the connection lost.

## 6. Streams

### 6.1 Reading

The core does not buffer (FR-BP-3), so the stream does. `on_data` runs inside the drain, so it cannot
wait: past the limit it resets the stream (D17). Reads leave through one method, which is where
credit will return bytes later (FR-AST-7).

```python
class Stream:
    def on_data(self, chunk):
        if self.closed: return
        self.read_buffer.append(chunk)
        self.read_bytes += len(chunk)
        self.read_high_water = max(self.read_high_water, self.read_bytes)
        if self.read_bytes > self.max_read_buffer:
            self.host.core.reset_stream(self.id, LIMIT_EXCEEDED)   # STREAM_CLOSED follows in this drain
            return
        self.readable.set()

    async def read(self):
        while True:
            if self.reset_code is not None:      # a reset wins over buffered data (D18)
                raise StreamReset(self.reset_code)
            if self.read_buffer:
                return self._take()
            if self.remote_eof or self.closed:
                return END_OF_STREAM             # b"" or null
            self.readable.clear()
            await self.readable.wait()

    def _take(self):
        chunk = self.read_buffer.popleft()
        self.read_bytes -= len(chunk)
        return chunk
```

### 6.2 Writing

```python
    async def write(self, data):
        if not data:
            return                               # an empty DATA frame is a protocol error
        async with self.write_lock:              # FIFO: concurrent writes do not interleave
            view = memoryview(data)
            while view:
                self._check_writable()           # re-checked after every wait
                self.writable.clear()            # before the call, so its WRITABLE is not lost
                piece = view[:MAX_WRITE_CALL]    # the binding copies: this keeps it linear
                accepted = self.host.call(core.write, self.id, piece, now_ms())
                view = view[accepted:]
                if accepted < len(piece):
                    await self.writable.wait()

    def on_closed(self, code):
        self.closed = True
        if code != OK:
            self.reset_code = code
        self.readable.set(); self.writable.set(); self.accepted.set(); self.finished.set()
```

`MAX_WRITE_CALL` is `max_queued_bytes_per_stream`: a single call cannot accept more.

Cancelling a write releases the lock. Bytes already accepted stay queued, so a cancelled write leaves
an unknown amount sent, like `TRANSPORT_LOST` does. Writing and resetting check `closed` first, and
never reach the core for a closed stream.

### 6.3 Handlers

```python
def spawn_handler(handler, request):
    async def run():
        try:
            await handler(request)
        except Reject as e:
            request.settle_rejected(e.code, e.message)
        except CancelledError:
            raise
        except Exception as e:
            log(e)
            request.settle_failed()              # CONNECT_FAILED, or KILLED if accepted
        else:
            request.settle_returned()            # POLICY_DENIED, or EOF if accepted
    host.handler_tasks.add(spawn(run()))
```

### 6.4 Params validation

Both directions run the same field check, so what one side can send, the other accepts. Outgoing, a
mismatch is the caller's bug: `open_stream` raises `InvalidParams` and nothing is sent. Incoming, it
is untrusted input: the stream is rejected with `PROTOCOL_ERROR`, the handler does not run, and the
connection stays up.

```python
def encode_params(stream_type, value) -> bytes:
    check_fields(stream_type.fields, as_mapping(value))
    return json.dumps(as_mapping(value), separators=(",", ":")).encode("utf-8")

def decode_params(stream_type, data: bytes):
    try:
        text = data.decode("utf-8")                         # strict
        parsed = json.loads(text, parse_constant=refuse)    # NaN and Infinity are not JSON
    except ValueError as e:
        raise InvalidParams(e)
    if not isinstance(parsed, dict):
        raise InvalidParams("params are not an object")

    values = {}
    for field in stream_type.fields:                        # undeclared keys are ignored
        if field.name in parsed:
            values[field.name] = check_value(field, parsed[field.name])
        elif field.has_default:
            values[field.name] = field.default
        else:
            raise InvalidParams(f"missing field {field.name}")
    return stream_type.build(values)

def check_value(field, value):
    if value is None:
        return value if field.nullable else invalid(field)
    match field.type:
        case "string": ok = isinstance(value, str)
        case "bool":   ok = isinstance(value, bool)
        case "float":  ok = is_number(value)                # bool is not a number
        case "int":
            if is_number(value) and is_whole(value) and abs(value) <= 2**53 - 1:
                return int(value)                           # 5037.0 becomes 5037
            ok = False
    return value if ok else invalid(field)
```

The two languages do not behave alike by default, so each rule below is written into the validator
and has a conformance case:

| Input | Default behaviour | Rule |
|---|---|---|
| Invalid UTF-8 | Python raises; `TextDecoder` replaces the bytes silently | Rejected. JS uses `fatal: true` |
| `NaN`, `Infinity` | Python's `json` accepts them; `JSON.parse` refuses | Rejected. Python uses `parse_constant` |
| `true` for an int field | In Python, `bool` is an `int` | Rejected in both |
| `5037.0` for an int field | JS cannot tell it from `5037` | Accepted in both, as `5037` |
| An int above 2^53 − 1 | JS rounds it silently; Python keeps it exact | Rejected in both |

## 7. Client

`Client` is a state machine with one class per state, as in the core (D12). The dialing states start
the dial loop on entry, so nothing else in the client knows about retries.

| State | handshake done | connection lost | session closed | dial gave up | `close()` | `open_stream` |
|---|---|---|---|---|---|---|
| `CONNECTING` | → `CONNECTED` | next attempt | → `CLOSED` | → `CLOSED` | → `CLOSED` | waits |
| `CONNECTED` | - | → `RECONNECTING` | → `CLOSED` | - | `GOAWAY`, → `CLOSED` | opens |
| `RECONNECTING` | → `CONNECTED` | next attempt | → `CLOSED` | → `CLOSED` | → `CLOSED` | waits |
| `CLOSED` | - | - | - | - | - | raises |

`CONNECTING` differs from `RECONNECTING` in one way: `connect()` is still waiting, and it gives up
after `connect_timeout` with `NoConnection`. Once `connect()` has returned, there is no attempt limit
(D15).

```python
async def connect(dial, *, handlers=None, capabilities=b"", options=None):
    options = options or ClientOptions()
    client = Client(dial, new_session_id(), handlers, capabilities, options)  # loads WASM in TS
    client.enter(ConnectingState)
    try:
        await wait_for(client.first_outcome, options.connect_timeout)
    except TimeoutError:
        await client.abandon()
        raise NoConnection(client.last_dial_error)
    return client                                # or raises close_error

def new_session_id() -> str:
    return secrets.token_hex(16)                 # TS: crypto.getRandomValues, which also works on
                                                 # plain http, where randomUUID does not exist

class DialingState(ClientStateBase):
    def on_enter(self):
        self.task = spawn(self._dial_loop())

    def on_exit(self):
        cancel(self.task)

    async def _dial_loop(self):
        attempt = 0
        while True:
            try:
                transport = await wait_for(client.dial(client.session_id), connect_timeout)
                check_message_size(transport, core_limits)   # FR-TP-4
                connection = client.host.attach(transport)
                await connection.wait_settled()   # handshake done, or the connection ended
                if client.host.connected:
                    return                        # the CONNECTED handler moved us on
            except GiveUp as e:
                client.fail(e)
                return
            except Exception as e:
                client.last_dial_error = e
            await sleep(backoff[min(attempt, len(backoff) - 1)])
            attempt += 1

class ConnectedState(ClientStateBase):
    def on_connection_lost(self):
        return RECONNECTING

    async def open_stream(self, kind, params):
        return client.host.open(kind, params)     # maps LIMIT_EXCEEDED, IDS_EXHAUSTED

class ClosedState(ClientStateBase):
    def on_enter(self):
        resolve_waiters(client.close_error)
```

`GOAWAY` reaches the client as `SESSION_CLOSED`. The code picks the error: `SESSION_NOT_FOUND` gives
`SessionNotFound`, anything else gives `SessionClosed(code)`. Reconnect stops in both cases. After a
refused re-dial, the state can read `CONNECTED` for a moment, because `HELLO` arrives before `GOAWAY`.

`close()` calls `core.close(code)` and waits for `SESSION_CLOSED` and for the connection's
`_shutdown`, then releases the core. It is idempotent.

## 8. Server

```python
class Server:
    async def serve(self, transport, context=None):
        try:
            first = await wait_for(transport.recv(), hello_timeout)      # FR-SRV-2
            hello = decode_frame(first)
            if hello.type != HELLO:
                raise CodecError
        except (TimeoutError, TransportClosed, CodecError):
            await transport.close()
            return

        existing = self._sessions.get(hello.session_id)
        try:
            data = await self.authorize(ConnectRequest(..., session=existing))   # FR-SRV-3
        except Refuse as e:
            return await self._refuse(transport, hello, e.code)

        session = self._sessions.get(hello.session_id)   # authorize may have waited
        if session is None:
            if hello.resuming:
                return await self._refuse(transport, hello, SESSION_NOT_FOUND)   # FR-SRV-9
            if len(self._sessions) >= max_sessions:
                return await self._refuse(transport, hello, LIMIT_EXCEEDED)      # FR-SRV-6
            session = self._create(hello, data)

        check_message_size(transport, core_limits)
        session.cancel_grace()
        connection = session.host.attach(transport, first_message=first)
        await connection.wait_closed()

    async def _refuse(self, transport, hello, code):
        """HELLO first: anything else before it is a protocol error (FR-HS-2)."""
        await transport.send(encode_frame(Frame(HELLO, session_id=hello.session_id, ...)))
        await transport.send(encode_frame(Frame(GOAWAY, code=code)))
        await wait_for_at_most(transport.wait_buffer_below(1), drain_timeout)
        await transport.close()

class ServerSession:
    def on_lost(self, event, replaced):
        if not replaced:                          # FR-SRV-4
            self.grace_timer = call_later(grace_period, self._expire)

    def _expire(self):
        spawn(self.close(TIMEOUT))                # FR-SRV-5

    def on_closed(self, event):
        self.server._sessions.pop(self.session_id)
```

A `resuming` client that the server does not know never gets a session, so a client's stream ID state
always belongs to a real peer. A first-time `HELLO` for an ID that exists replaces the connection,
because a client whose handshake failed retries with `resuming` still false (FR-HS-7).

## 9. Packaging (D20)

**Wheel.** `uv run scripts/build.py wheel` builds the Release library, copies it into
`packetmux/core/`, and builds with hatchling. A small `hatch_build.py` marks the wheel as platform
specific and tags it `py3-none-<platform>`: ctypes has no Python ABI dependency, so one wheel serves
every Python from 3.12 up. It then works as:

```sh
pip install packetmux-0.2.0-py3-none-macosx_11_0_arm64.whl
```

```toml
[project]
dependencies = ["packetmux @ file:///path/to/packetmux-0.2.0-py3-none-macosx_11_0_arm64.whl"]
```

This needs two changes to the library, both already on the list for RemoteDevice's `main`:

| Change | Why |
|---|---|
| Set `CMAKE_OSX_DEPLOYMENT_TARGET` to 11.0 | The dylib says `minos 26.0` today. It would not load on older Macs, and the tag has to tell the truth |
| Hide symbols by default, and export `PACKETMUX_API` | 319 symbols are exported today, 23 intended. A wheel ships into other people's processes |

**npm.** Remove `private`, add `files` with `dist/`, and add `exports` for `.`, `./core` and
`./testing`. `npm pack` gives an installable `.tgz`. `loadPacketMux` gains an optional `wasmUrl` for
bundlers that move the file. `connect` and `Server` call it without arguments, and a consumer that
needs the option calls it first.

Where packages are published (PyPI, npm, a private index) is not decided, and does not affect the
design.

## 11. Decisions made here

| # | Decision | Why |
|---|---|---|
| 1 | Handlers accept explicitly, through `IncomingStream` | An async check can come first, and accepting on first write can deadlock (§2.4) |
| 2 | `Refuse` answers `HELLO` and `GOAWAY(code)` | A refused client then stops retrying, rather than re-dialing forever |
| 3 | A handler that returns leaves its stream open until the peer's `EOF` | Resetting would throw away a reply the peer has not read yet (D18). If the peer never sends `EOF`, the stream stays until the session ends |
| 4 | The first `connect()` retries with backoff until `connect_timeout` | A brief network failure at start-up should not raise. After that, D15 applies |
| 5 | TypeScript `Transport` pulls with `recv`, with `PushTransport` as a helper | One reader loop and one conformance layer. It costs a promise per message, which NFR-SDK-5 will measure |
| 6 | Typed params with validators of our own, raw `bytes` still available | Friendlier than handling bytes, and the kind and fields are declared once. The wire does not change (FR-WIRE-5, D23) |
| 7 | `label` and the stream policy hook are dropped from today's hosts | `kind` and handlers cover both, and consumers can carry their own label |
